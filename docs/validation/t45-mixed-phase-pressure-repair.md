# #45：混合阶段 KV 压力恢复的最小修复范围

## 归属与边界

在不拆分原 19 个 Ticket、不改变 31 条原生依赖的前提下，#45 承担分层验证发现的混合 chunked-prefill/decode 压力恢复缺陷的最小修复，并交付对应回归证据。

这是对 #37/#38/#40 既有行为契约的补救，不替换它们的一般职责、原始验收义务或历史记录。既有交付记录不得当作该反例已通过的证据。#45 和最终发布必须包含修复后的相关重新验证；历史失败与未完成的数值验收不能重标为 PASS。

修改边界是 Scheduler 的工作选择、实际 decode append 需求与压力恢复协调，必要时使用现有 KVCacheManager 契约。可以安全抢占受害请求或推迟工作/准入，但不能新增公共 API、绕过内部无环依赖规则、改变模型/attention 数学，或调整精度预算。

## 必须保留的公开接口回归

通过真实 `LLM::generate`、Scheduler、KV 所有权和 StepPlan 执行；模型可以使用独立的 CPU 因果指纹测试替身。此结构测试不启用 forcing 或 GPU 采集器，也不表示 GPU 数值正确。

| 项目 | 固定输入 |
| --- | --- |
| prompt A | 512 个 token ID 1 |
| prompt B | 255 个 token ID 2 |
| completion 预算 | A=4，B=5 |
| 采样 | greedy，无 penalty，ignore_eos=true |
| context 上限 | 768，含 completion 预算 |
| 每步 token 预算 | 128 |
| 物理 KV | 3 个 block，每 block 256 token，prefix cache 开启 |
| 最大并发请求 | 2 |

该配置必须完成，并与只改为 4 个 block 的并发对照、只改为最大并发 1 的同容量对照产生相同的有序 token 输出。请求身份、完成状态、SamplingParams 与逻辑历史必须正确；完成和错误清理都不得泄漏 block。

不能因为还有 initial prefill 就跳过所有实际 decode append 压力处理，也不能简单移除保护而让精确容量的纯 prefill 请求反复重启。不得把合法的临时资源竞争改判为不支持输入、静默丢失请求，或通过增大上述固定预算、关闭 prefix cache、删除/忽略回归来获得通过。

## 修复必须维持的性质

- StepPlan 只包含能以真实物理所有权安全执行的工作；不能回收本轮仍被有效计划使用的 block。
- 释放、重新绑定和失败回滚保持事务性，完整保留 prompt 与已生成 token，以及请求的 SamplingParams。
- 恢复执行遵守分块和每步 token 预算，不能在所需历史恢复前采样。
- 纯 prefill 的精确容量进展、混合批次公平性、重复抢占、请求次序与身份均须保持。
- 确实不可满足的资源请求和不可恢复的分配错误仍给出明确错误并清理所有权；不能吞掉异常或无限重试。
- 原事件/运行环境/自由生成报告的审查修复仍需完整验证；调度修复不豁免它们。

## 证据与后续步骤

保留固定反例的 RED→GREEN、上述两个对照、现有精确容量/公平性/事务回滚/重复恢复测试，以及完整候选的项目 CPU gates 和新的完整双轴代码审查。仅一条回归转绿不足以完成 #45。

用例注册表后续冻结必须以实际事件证明所声称的机制。旧 KV 重算需要重新执行已计算过的历史区间；仅恢复 prefill 标签、命中 prefix cache 后计算新 token，不构成旧区间重算。较大每步预算的成功场景不能消除本文件的 128-token 回归义务。

本文件只授权上述 CPU 实现与验证。它不冻结待修订的用例注册表，不批准任何 L0/L1/L2 数值预算，不授权 CUDA 构建、GPU 采集、查看未获准的独立验收数值、tag/release/asset 发布，也不将任何 Ticket 自动标记为已接受。

其余分层验证规则继续由[分层精度契约](layered-accuracy-contract.md)与 [ADR-0015](../adr/0015-layered-accuracy-validation.md)约束。
