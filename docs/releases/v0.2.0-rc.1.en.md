# v0.2.0.rc.1 — Qwen3 offline inference release candidate

**Released: 2026-09-10 · Status: historical experimental prerelease · [中文](https://github.com/RedHeartSecretMan/vllm-oxide/blob/main/docs/releases/v0.2.0-rc.1.md)**

RC1 provided a Rust/CUDA single-GPU Qwen3 offline source snapshot for trial and feedback. **New users should use [v0.2.0](https://github.com/RedHeartSecretMan/vllm-oxide/releases/tag/v0.2.0).** RC1's incomplete numerical and performance validation remains part of its historical record; it does not describe the current release.

## Highlights

- Provide Qwen3-0.6B/BF16 through the synchronous single-GPU `LLM::generate` interface.
- Include continuous batching, paged KV cache, prefix caching, waiting admission, chunked prefill and recompute preemption.
- Add bounded supervision and validation tooling while retaining the original numerical budgets and measurement identities.
- Prepare the prerelease version and forward the CLI's `cuda` feature; RC finalization did not alter inference operators, weights or validation inputs.

## Compatibility and migration

The recorded environment was **RTX 4080/WSL2 with Rust 1.94.0**. Inference requires Linux (including WSL2), an SM 8.9+ NVIDIA GPU, a compatible CUDA driver, the CUDA Toolkit and model files. The historical Cargo manifest's Rust 1.75 minimum was **not validated**; use the recorded Rust 1.94.0 environment when reproducing RC results.

The Git tag is **`v0.2.0.rc.1`**, while the Cargo package version is `0.2.0-rc.1`; this historical spelling is preserved. For the supported API and current requirements, upgrade to v0.2.0 and follow the [migration guide](https://github.com/RedHeartSecretMan/vllm-oxide/blob/main/docs/migration-v0.2.0.md).

## Get the source

```bash
git clone --branch v0.2.0.rc.1 --depth 1 https://github.com/RedHeartSecretMan/vllm-oxide.git
cd vllm-oxide
cargo run --locked --release -p vllm_oxide_cli --features cuda -- \
    --model /path/to/Qwen3-0.6B --max-tokens 2 "The capital of France is"
```

The model directory must contain `Qwen/Qwen3-0.6B@7e4ae267688d671ddfca3122e4528ee980cf3234`. The CLI also accepts a Hub repository ID, but that form has no revision flag and does not pin the validated checkpoint. CPU-only builds are for development and tests, not model inference.

## Validation and performance

The original verification was **not fully passing**:

| Recorded check | Historical result |
|---|---|
| Basic functionality | CPU checks, CUDA CLI build and short generation passed; two independent short generations agreed |
| Capture completeness | 487/487 capture items and 153/153 capture groups verified |
| Numerical comparisons | 48 of 66 passed; 18 failed |
| Operators and public behavior | Seven operator profiles and 22 behavior checks passed |
| Performance and minimum toolchain | Full performance validation and the declared Rust minimum were incomplete |

Short generation and CPU CI do not override the numerical failures. No RC performance guarantee is claimed. v0.2.0's later acceptance belongs to its own source identities and does not relabel RC1 as passing.

## Known limitations

This historical prerelease has 18 numerical failures and provides no production accuracy guarantee. Full performance and the declared Rust minimum were unverified at publication. These are limitations of RC1, which has been superseded by v0.2.0.

Serving/async/streaming APIs, multi-GPU/TP/NCCL, other model families, quantization, LoRA, speculative decoding and CUDA Graphs are outside this prerelease's scope.
