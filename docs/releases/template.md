# Release notes template

Copy the sections below into the next release's notes, replacing placeholders and removing sections that do not apply. Keep the opening useful to an inference user; link detailed validation rather than pasting raw logs.

---

# vVERSION — release headline

One or two sentences describing the user-visible result and the supported inference scope.

## Highlights

- The most useful behavior or feature added.
- A correctness or performance problem fixed, with its observable effect.

## Compatibility and migration

State the Rust/toolchain and CUDA requirements. List breaking API or behavior changes and link a version-specific migration guide. Include the previous-to-current comparison link.

## Install and run

Provide a complete command that selects this published tag and a supported model. State whether the artifacts are source archives or tested binaries, and which features enable inference.

```bash
git clone --branch vVERSION --depth 1 https://github.com/RedHeartSecretMan/vllm-oxide.git
cd vllm-oxide
# Add the actual, checked build or run command here.
```

## Validation and performance

Summarize the actual CPU, numerical and public CUDA checks. Name the model revision, dtype and GPU environment. Give workload/configuration, sample count and units for any performance numbers, with a link to complete provenance. Hardware-specific timing is a baseline rather than a universal guarantee.

## Known limitations

Describe the unsupported functionality relevant to a user, any outstanding issue affecting the supported scope, and any separate evidence packaging or distribution work that is not being claimed complete.

## Contributors and changes

Review and append the categorized PR/contributor summary generated by GitHub. Include all relevant fixes; remove unrelated internal bookkeeping. Link the complete changelog and comparison.
