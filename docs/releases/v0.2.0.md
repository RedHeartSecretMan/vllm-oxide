# v0.2.0 — 发布范围与证据

正式发布需要通过完整门禁，并附带 `docs/releases/goldens-v0.2.md` 及其绑定的原始证据。版本号本身不表示数值验收通过；报告必须对应实际发布的源码和二进制。历史 [RC1](v0.2.0-rc.1.md) 的失败记录保留原样。

## 支持范围

- 单 GPU、Qwen3-0.6B、BF16、同步离线 `LLM::generate`。
- 持续批处理、分页 KV、prefix cache、等待准入和抢占重算。
- 公共 Rust 接口为 `LLM`、`EngineOptions`、`Prompt`、`SamplingParams`、`RequestOutput`、`Source`。
- Rust 1.94 或更新版本；实际模型推理需要 `--features cuda`。发布验证环境为 Linux/WSL2、RTX 4080、CUDA toolkit 13.2.51，固定模型 revision 为 `7e4ae267688d671ddfca3122e4528ee980cf3234`。
- 不包含服务 API、多 GPU/TP/NCCL、其他模型族、量化、LoRA、speculative decoding 或 CUDA Graphs。

## 当前修复与证据

独立 QKV/MLP 投影、精确归约顺序的 RMSNorm、有界 FP32 attention 与批次形状对齐已修复已定位的数值误差。开发复验提交 `f7d2b454e1c7d2d08607376e2a546a5be7fafd65` 的 28 个开发用例与原始参考 logits 逐位一致；同一提交通过 100 次重复公共 API 调用、混合批次和 CLI smoke，远端 CPU CI 全绿。这些是带原始来源的开发证据，不能重标为最终 v0.2.0 的校准或独立验收。

已验证的算术修复使用 `fp32-causal-math-v1` kernel 身份。数值上限保持平均 KL 0.002、峰值 KL 0.005、相对 vLLM 平均额外 KL 0.001、参考选择损失 `ln(1.25)`，每个 case 独立检查。完整校准、故障注入、独立验收、重放、性能与干净消费者验证仍须绑定最终测量提交。新后端不会继承旧校准文件或遗失 ledger 的审批身份。

本分支另含 [ADR-0023](../adr/0023-proposed-explicit-gemm-reduction.md) 的精度草案：参考与候选共同关闭 BF16 GEMM 的中间低精度截断，候选身份为 `fp32-gemm-reduction+causal-math-v2`，参考身份包含 `fp32-gemm-reduction`。模型权重、激活与输出仍使用 BF16；原预算不变。该参考变更尚未获批，草案实验不能覆盖原始等待用例的失败，也不能作为发布验收。

## 正式发布条件

- 正式版本与性能 producer 来自同一干净测量提交，具备完整校准及对应审批绑定。
- 全部算子、数值、公开行为、重放/control 和性能证据完整有效，门禁保持失败关闭。
- `goldens-v0.2` 的 manifest/archive 双资产通过干净消费者验证，记录精确哈希、运行环境和源码来源。
- 最终评审与 issue 验收完成后，才创建正式 v0.2.0 标签及 GitHub Release。
