# v0.2.0 — 单 GPU Qwen3 离线推理

2026-10-13 发布 · [GitHub Release](https://github.com/RedHeartSecretMan/vllm-oxide/releases/tag/v0.2.0) · [English](v0.2.0.en.md)

v0.2.0 完善了 Rust/CUDA 离线生成的正确性，修复批处理、缓存复用、抢占重算和重复调用中的问题。支持范围是单 GPU、Qwen3-0.6B、BF16、同步 `LLM::generate`。

## 本版重点

- 请求标识、输入输出顺序、token 历史和每条请求的采样策略在调度和重复生成中保持一致。
- 持续批处理、等待准入、chunked prefill、prefix cache 和抢占重算使用完整因果历史与统一 token/KV 预算。
- 独立 QKV/MLP 投影、FP32 GEMM 中间归约、参考顺序 RMSNorm、有界因果 attention 和 `call-layout-v2` 修复数值及批次布局误差。
- Rust 1.94/stable、Python CPU 工具与依赖审计形成自动 CI；真实 CUDA 功能、模型精度和性能由本地 GPU 验证。

## 升级与兼容性

**这是一次 pre-1.0 的破坏性 API 升级。** 公共 crate-root 仅保留 `LLM`、`EngineOptions`、`Prompt`、`SamplingParams`、`RequestOutput` 和 `Source`。内部调度、缓存、loader/model 和 sampler 类型不再导出，`LLM::generate_logits` 移除，输出标识从 `seq_id` 改为 `request_id`。详见[迁移指南](../migration-v0.2.0.md)。

最低 Rust 版本为 1.94。CPU 开发无需 CUDA；推理需要 Linux（包括 WSL2）、SM 8.9 或更新的 NVIDIA GPU、可用驱动和包含 `nvcc` 的 CUDA Toolkit。本版实测环境为 RTX 4080/WSL2、驱动 595.71、Toolkit 13.2.51。

## 获取源码并运行

```bash
git clone --branch v0.2.0 --depth 1 https://github.com/RedHeartSecretMan/vllm-oxide.git
cd vllm-oxide
cargo run --locked --release -p vllm_oxide --example generate_qwen3 --features cuda -- \
    hub:Qwen/Qwen3-0.6B@7e4ae267688d671ddfca3122e4528ee980cf3234
```

首次运行会构建 CUDA 后端并下载固定 revision 的模型；随后复用本地缓存。自定义 prompt、CLI、本地 checkpoint 和 Rust API 用法见[使用指南](../getting-started.md)。

## 已完成的验证

- 原独立验收覆盖 **747/747** 个采集项、**231/231** 个执行组，包含 104 项数值比较、44 项行为检查和 7 项算子检查，原数值预算保持不变。
- 发布实现通过生产 CUDA 构建、真实 warmup、100 次重复公开 API 调用、3 个混合请求及 CLI；107 个请求 ID 唯一，已验证的 Quick Start CLI 输出 `Paris.`。
- 两个性能工作负载各丢弃一次 warmup 后测量三次；六次测量全部通过原始输出、时序、统计和严格 50ms 显存采样时序检查。
- 发布 PR 最终四项 CPU CI 全部通过；合并源码树与受测候选完全一致。

RTX 4080/WSL2、固定 Qwen3-0.6B/BF16 工作负载的中位数如下。batch 吞吐为四请求总吞吐：

| 工作负载 | Decode token/s | TTFT ms | 峰值显存 MiB |
|---|---:|---:|---:|
| 单请求 | 29.7601 | 40.9622 | 10756 |
| 四请求 batch | 115.8207 | 36.7626 | 10692 |

这些数值是该环境的基线，不是跨硬件最低吞吐保证或与 vLLM 的性能对等声明。完整指标、数值预算、固定来源和哈希见[验证摘要](goldens-v0.2.md)。

## 发行物与限制

本次提供 GitHub 生成的源码 `.tar.gz` 和 `.zip`，Rust 依赖通过 `v0.2.0` Git tag 获取。完整原始证据保留在本地；旧组合证据包的完整独立消费者门禁未声明完成。

v0.2.0 不包含服务/异步/流式 API、多 GPU/TP/NCCL、其他模型族、量化、LoRA、speculative decoding 或 CUDA Graphs。默认 KV cache 使用较大比例的剩余 GPU 内存；需要预留显存时，可通过 Rust `EngineOptions` 调整预算。
