# v0.1.0 — Experimental Qwen3 offline inference

**Released: 2026-07-26 · Status: historical experimental release · [中文](https://github.com/RedHeartSecretMan/vllm-oxide/blob/main/docs/releases/v0.1.0.md)**

v0.1.0 introduced the Rust/CUDA single-GPU Qwen3 offline engine and reference fixtures from Transformers and vLLM. **New users should use [v0.2.0](https://github.com/RedHeartSecretMan/vllm-oxide/releases/tag/v0.2.0).** This preserved snapshot has known accuracy failures and is retained for historical comparison.

## Highlights

- Introduce synchronous `LLM::new` / `LLM::generate`, per-prompt sampling and a thin offline CLI.
- Implement continuous batching, paged KV cache, prefix caching and recompute preemption for single-GPU Qwen3 generation.
- Provide greedy, top-k and top-p sampling with repetition, presence and frequency penalties.
- Attach Transformers/vLLM comparison fixtures with model/runtime provenance and per-fixture checksums.

## Compatibility and migration

The recorded validation used **Qwen3-0.6B/BF16 on RTX 4080/WSL2**. Inference requires Linux (including WSL2), an SM 8.9+ NVIDIA GPU, a compatible CUDA driver, the CUDA Toolkit and local model files. No prebuilt binaries or model weights are provided.

The tagged Cargo manifest declares Rust 1.75; this historical minimum was not established by the later Rust 1.94/stable CI matrix. Do not apply current v0.2.0 validation or API guarantees to this snapshot. The [migration guide](https://github.com/RedHeartSecretMan/vllm-oxide/blob/main/docs/migration-v0.2.0.md) explains the breaking upgrade to v0.2.0, including the narrower public API and `seq_id` → `request_id` change.

## Get the source

```bash
git clone --branch v0.1.0 --depth 1 https://github.com/RedHeartSecretMan/vllm-oxide.git
cd vllm-oxide
```

This selects the historical implementation with its documentation-maintenance update. For a supported build and generation walkthrough, use the [current getting-started guide](https://github.com/RedHeartSecretMan/vllm-oxide/blob/main/docs/getting-started.md) with v0.2.0 instead.

## Validation and performance

The original verification was **not fully passing**:

| Recorded check | Historical result |
|---|---|
| Fixture coverage | 28 prompt groups × two reference implementations = 56 fixtures |
| Logit coverage | Eight groups with full logits; 20 groups with top-5 data |
| Full-output token agreement | Four of eight groups passed; four differed |
| Absolute logit tolerance | `66.46875` |
| Regression exclusions | Six regression cases contain skipped positions |

These results do not establish the stricter v0.2.0 accuracy contract. No validated release performance baseline is claimed for this version.

## Known limitations

The historical numerical failures and skipped comparisons remain unchanged; this version provides no production accuracy guarantee. It is a synchronous offline engine without serving/async/streaming APIs or supported multi-GPU/TP/NCCL inference. Additional model families, quantization, LoRA, speculative decoding and CUDA Graphs are outside the release scope.
