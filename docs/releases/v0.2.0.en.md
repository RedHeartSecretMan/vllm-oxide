# v0.2.0 — Single-GPU Qwen3 offline inference

Released on 2026-10-13. v0.2.0 hardens Rust/CUDA offline generation, fixing correctness during batching, cache reuse, recompute preemption and repeated calls. The supported workload is **Qwen3-0.6B/BF16 on one GPU**, through the synchronous `LLM::new` / `LLM::generate` API.

## Highlights

- Preserve request identity, input/output order, token history and each request's sampling policy across scheduling and repeated generation.
- Complete continuous batching, waiting admission, chunked prefill, prefix caching and recompute preemption with consistent causal history and token/KV budgets.
- Fix numerical and batch-layout errors with independent QKV/MLP projections, explicit FP32 GEMM reduction, reference-ordered RMSNorm, bounded causal attention and `call-layout-v2`.

## Breaking API changes

The supported crate-root exports are now `LLM`, `EngineOptions`, `Prompt`, `SamplingParams`, `RequestOutput` and `Source`. Internal scheduler/cache/loader/model/sampler types and `LLM::generate_logits` are no longer public. Replace `RequestOutput.seq_id` with `request_id`, and associate outputs with prompts by their vector position.

See the [v0.1 to v0.2 migration guide](https://github.com/RedHeartSecretMan/vllm-oxide/blob/main/docs/migration-v0.2.0.md) for the supported API and stricter input validation.

## Install and run

This is a **source release**. GitHub provides source `.tar.gz` and `.zip` archives; Rust applications can depend on the `v0.2.0` Git tag.

Inference requires Rust **1.94+**, Linux (including WSL2), an NVIDIA GPU with **SM 8.9+**, a compatible driver and the CUDA Toolkit including `nvcc`. CPU development does not require CUDA. The release was validated on RTX 4080/WSL2 with driver 595.71 and Toolkit 13.2.51.

```bash
git clone --branch v0.2.0 --depth 1 https://github.com/RedHeartSecretMan/vllm-oxide.git
cd vllm-oxide
cargo run --locked --release -p vllm_oxide --example generate_qwen3 --features cuda -- \
    hub:Qwen/Qwen3-0.6B@7e4ae267688d671ddfca3122e4528ee980cf3234
```

The first run builds CUDA kernels and downloads the pinned checkpoint. Later runs reuse cached files. See [getting started](https://github.com/RedHeartSecretMan/vllm-oxide/blob/main/docs/getting-started.md) for custom prompts, the CLI, local checkpoints and Rust examples.

## Validation and performance

- Independent numerical acceptance: **747/747** capture owners and **231/231** execution groups passed, including 104 numerical comparisons, 44 behavior checks and seven operator checks. Approved numerical budgets are unchanged.
- Actual CUDA API/CLI smoke passed: production build, real warmup, 100 repeated API calls, three mixed requests, 107 unique request IDs and the tested Quick Start CLI output `Paris.`.
- Both fixed performance workloads passed all six measured repetitions and the original strict 50ms memory-sampling timing limits.
- The release PR passed all four CPU CI jobs; the merged source tree matched the tested candidate. GPU validation ran locally.

On the fixed RTX 4080/WSL2 Qwen3-0.6B/BF16 workload, medians were:

| Workload | Decode token/s | TTFT ms | Peak memory MiB |
|---|---:|---:|---:|
| One request | 29.7601 | 40.9622 | 10756 |
| Four-request batch, total throughput | 115.8207 | 36.7626 | 10692 |

These are environment-specific baselines, not cross-hardware throughput guarantees or vLLM-parity claims. Default KV cache sizing uses a substantial share of remaining free GPU memory; applications can tune its budget through Rust `EngineOptions`.

## Known limitations

Serving/async/streaming APIs, multi-GPU/TP/NCCL, other model families, quantization, LoRA, speculative decoding and CUDA Graphs are outside this release.

Full raw acceptance evidence remains local. The separate legacy combined evidence-package consumer gate is not claimed complete.
