# Contract v0.2.0 around LLM::generate

v0.1 exposed engine, sequence, cache, attention, loader, registry, model, sampler, and utility types from the crate root even though the supported product is offline generation. v0.2.0 is a deliberate pre-1.0 breaking contraction: the default crate-root exports are exactly `LLM`, `EngineOptions`, `Prompt`, `SamplingParams`, `RequestOutput`, and `Source`; the supported `LLM` operations are construction through `LLM::new` and generation through `LLM::generate`.

No compatibility aliases or root re-exports remain for `Sampler`, utility helpers, attention metadata or cache types, engine and scheduler types, loader helpers or resolved identities, `CausalLM`, registry types, `BuiltModel`, or `build_model`. Workspace consumers and the CLI use the same six-type surface. The private prepared-attention state moves into the now-internal `AttentionContext`, so Ticket #42's temporary public-field, direct-forward, and `PagedKVCache` sidecar compatibility bridge is removed without changing one-prepare-per-step behavior.

Public methods keep their existing `anyhow::Result` signatures; `anyhow::Error` is a transitive external error type, not a project alias or root re-export. `EngineOptions::dtype` keeps `Option<candle_core::DType>` as a transitive external configuration type, also without a root re-export. These signature types do not expand the supported vllm-oxide namespace.

The GPU release gate still needs raw same-prefix logits for L2 comparison, but that capability is not a user generation API. A default-off Cargo feature named `internal-golden` enables a crate-internal, process-scoped raw-logit capture sink selected by reserved environment configuration; it adds no public Rust module, trait, method, or type. The workspace `vllm-oxide-test` crate still imports only the six supported types and calls `LLM::new` / `LLM::generate`, then consumes the temporary diagnostic artifact. Any downstream can enable a Cargo feature, so this is an unsupported release-tooling behavior rather than an access-control claim or semver API.

Enabling the feature alone is inert: absent capture configuration performs normal generation with no diagnostic I/O, while a present but invalid configuration fails before request admission. Valid configuration names a caller-owned private temporary location, a fresh non-existing destination, and a per-call identity. Capture must not follow a destination symlink, reuse, open, or replace an existing destination. `LLM::generate` reports success only after the complete artifact is serialized to private staging, checked, and atomically published without replacement; a collision or any capture, serialization, write, validation, or publication failure fails the call and cannot expose a partial final artifact.

Every artifact binds the configured call identity to the exact invocation, input position and stable `request_id` for every request, the selected token and zero-based completion step for every logits row, deterministic row ordering, and the complete tensor shape and dtype. The consumer validates these bindings against the returned `RequestOutput` values and rejects duplicate, non-contiguous, missing, additional, stale, or shape-inconsistent rows before L1 or L2 comparison. Thus diagnostic capture may copy full logits to the host only when explicitly active, while same-prefix evidence remains attributable and fail-closed.

The v0.2.0 release notes must identify this contraction as breaking and point users to the composition-root API rather than preserving obsolete internals.

**Status**: accepted
