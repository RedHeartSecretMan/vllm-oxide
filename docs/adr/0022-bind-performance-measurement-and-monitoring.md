# Bind performance to the measured implementation and actual monitoring interval

A supervised release benchmark executes the immutable authoritative measurement checkout, not the newer supervisor checkout. Its binary has a separate `measurement_benchmark_binary` SHA-256/build identity in the selected supervision policy. Performance wrapper schema 2 binds that source and binary to the authoritative supervisor/policy, the native command, a complete schema-2 guard timeline and the original telemetry closure. An absent binding or legacy performance wrapper cannot satisfy a supervised release. The same pinned GPU-only Python environment is checked before and after the owner runs.

The native memory monitor requests samples every 10 ms and records the ceiling of the observed maximum interval. It rejects an actual `Duration` above 50 ms before any conversion to integer timestamps; the original 50 ms acceptance ceiling is unchanged. On the release host, requesting 50 ms yielded an observed 50.429 ms gap, while a 10 ms request yielded at most 10.435 ms in the diagnostic probe. The faster request provides scheduling margin but never excuses a late sample. The outer health supervisor retains its independent RAM/process checks and lower-rate single-flight telemetry; its recovery snapshots are not substitutes for benchmark peak-memory samples.

The benchmark still requires successful authoritative numerical evidence before collection, one discarded warm run and three measured repetitions for each frozen workload, complete public outputs and synchronized raw timestamps. These changes do not approve calibration, weaken a numerical or memory threshold, or claim that a performance gate has passed.
