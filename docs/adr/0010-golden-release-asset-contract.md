# Publish one manifest and one deterministic golden archive

For new layered releases, [ADR-0016](0016-layered-golden-release-assets.md) supersedes the schema4-only, fixtures-only and historical-field layout below. This decision remains the historical schema4 contract; its two-asset, integrity, immutable-install and publication safeguards continue under the new contract.

Ticket #43 replaces the per-fixture GitHub Release layout with one cross-language, fail-closed asset contract. The release asset set is exactly `manifest.json` and `goldens-v0.2.tar.gz`; source archives generated by GitHub are not release assets for this contract, and individual `.safetensors` files are never uploaded separately.

The existing Python/Rust golden `Manifest` is the single source of truth and advances from schema 3 to schema 4 rather than being wrapped by a second asset manifest. Schema 4 adds `product_version: "v0.2.0"`, `golden_version: "goldens-v0.2"`, and `archive: { filename: "goldens-v0.2.tar.gz", sha256: <64 lowercase hex> }`; existing `fixtures[].sha256` values remain the per-fixture identities. A consumer accepts only schema 4, the exact supported product/golden version pair, a release tag equal to `golden_version`, and the exact two-asset set.

The archive contains every and only `fixtures[].filename` at its root and never contains the manifest. Entries are sorted by canonical ASCII filename and are regular files with normalized mode `0644`, uid/gid `0`, empty owner/group names, and mtime `0`; the gzip header also has mtime `0` and no source filename. Absolute or nested paths, `.` or `..`, backslashes, non-UTF-8 names, links, directories, devices, FIFOs, duplicate names, undeclared entries, missing fixtures, and checksum mismatches fail closed.

The downloader verifies the standalone manifest, exact release assets, archive digest, entry set, and every extracted fixture before exposure. It extracts into a sibling staging directory and publishes with one rename to the immutable content-addressed path `<cache-root>/goldens-v0.2/<archive-sha256>`; an existing final directory is reused only after complete verification and otherwise causes an error without overwrite. Any download, parse, validation, extraction, or rename failure removes only the unpublished staging directory and leaves prior installs unchanged.

Python uses the standard library `tarfile`/`gzip` path for deterministic publication. The Rust consumer may add direct `tar` and `flate2` dependencies; this is preferred over a second schema or a less ubiquitous compression dependency. Real fixture generation and GitHub Release publication remain owned by Ticket #45.
