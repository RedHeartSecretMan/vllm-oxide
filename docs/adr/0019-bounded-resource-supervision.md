# Recover bounded telemetry faults without relabeling measurements

The user requested optimization of repeated resource-monitor timeouts and continuation of the remaining evidence. We adopt the [bounded supervision contract](../validation/layered-supervision-contract.md) and its [versioned policy](../validation/layered-supervision-policy.json): independent fast RAM/process protection, lower-rate single-flight GPU telemetry, and at most one fully recorded timeout recovery within a finite window. Persistent monitoring failure, real resource violations, failed workers and missing final cleanup evidence still stop the stage. This is resilience to an observed query failure, not a claim that its NVML/driver root cause has been fixed.

We keep actual numerical workers and the Rust binary at the immutable, already verified `8f21331` measurement source, while explicitly binding the new supervisor/evaluator implementation separately. Exactly 445 source- and hash-bound successful old owners are eligible for strict legacy-guard compatibility; 42 remaining owners use the new guard. Failed and diagnostic records remain immutable and excluded. No numerical input, model, kernel scope, budget, comparison formula or per-case rule changes; the original `6b7ae7d` calibration approval keeps its own identity and verification path.

**Supersedes only the incompatible supervision/source assumptions:** ADR-0012's requirement that one measurement commit contain all later supervision/evaluation bytes; ADR-0016 and the release asset contract's schema-1-only execution evidence and measurement-checkout-only evaluation; and the layered accuracy contract section 13 / ADR-0018 only where they prohibit this explicitly separated, reviewed supervision/identity adapter. This is not a general allowance for executable changes after measurement. The protected numerical paths, real immutable worker invocation, role-specific Git/CPU/review identities, exact retained ledger and complete closure checks define the exception. The outer release schema remains 5; new supervised execution manifests and guards are schema 2, with schema 2 authoritative markers bound to the actual evaluator. Original schema 1 predecessor evidence remains original.

Treating one slow query as immediate evidence failure caused aborts even after a worker exited successfully. Ignoring telemetry or fabricating fresh samples would lose trustworthy resource evidence; allowing arbitrary old guards or changing their source labels would lose provenance. The chosen bounded recovery and exact compatibility ledger avoid those changes while retaining the independent 16 GiB RAM floor and fresh preflight/final checks. Finite recovery can still fail, and the polling interval is not an OS hard-real-time guarantee.

**Status:** accepted supervision optimization and narrowly scoped evidence-reuse decision under the user's request. Implementation, complete CPU tests/review and actual remaining GPU evidence are still required. The original Ticket graph and accepted delivery obligations remain unchanged; this decision accepts no Ticket and does not authorize performance, tag/release/asset or other publication writes.
